# Реестр решений

| ID | Статус | Решение / причина |
|---|---|---|
| ADR-001 | принято в baseline | Amnezia Control вместо собственного VPN backend; модифицировать только недостающие scoped adapters и ownership UI |
| ADR-002 | действует | один bot/worker и единственный SQLite registry; никакой неподготовленной HA |
| ADR-003 | действует | numeric MAX ID — identity, имя/телефон не авторизация |
| ADR-004 | действует | unknown без blind retry и missing не равно revoked |
| ADR-005 | действует | личный MAX-проект отдельно от неутверждённого корпоративного Pachca-сервиса |
| ADR-006 | принято 2026-11-14 | публичный Git хранит код/обезличенные знания; operational secrets и live данные вне репозитория |
| ADR-007 | принято 2026-11-14 | сначала reproducible baseline; push не является production deployment |
| ADR-008 | выполнено 2026-11-14 | manager/бот на новом хосте; старая VPN-нода сохранена, новая co-hosted нода добавляется отдельно |
| ADR-009 | принято 2026-11-14 | доступность нод из сети с ограничениями проверяет внешний настоящий VPN-клиент, а не бот; бот только показывает результат при выборе сервера и не рассылает уведомлений |
| ADR-010 | принято 2026-11-14 | релиз кода бота — только из чистого commit сценарием `release.py`; образ помечается commit, панель и ноды этим путём не выкатываются |
| ADR-011 | принято 2026-11-14 | платёжная автоматизация и корпоративный Pachca-контур сняты с roadmap; оплата подтверждается вручную |
| ADR-012 | принято 2026-11-14 | название ключа, заданное владельцем в боте, хранится в реестре как метка и не меняет имя на ноде; переименование администратором в панели метку сбрасывает |

Каждое будущее изменение границ/хранения/координации оформлять новой записью с альтернативами,
миграцией, критериями приёмки и откатом. Не менять тихо смысл прежних paid slots и ownership.
