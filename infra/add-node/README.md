# Быстрое добавление запасной ноды

Адреса нод периодически блокируются и возвращаются сами через несколько дней. Заблокированную ноду
не чинят — держат запас доступных. Эта команда вводит новую ноду в работу целиком.

```
python3 infra/add-node/add_node.py --manager <ssh-alias manager> --host <адрес нового сервера> \
    --name "Amnezia — Город" --vantage <имя точки>=<ssh-alias точки проверки> [--port 47300] [--dry-run]
```

## До запуска

1. Новый сервер: Linux с Docker, вход по SSH для пользователя из `--ssh-user` (по умолчанию root).
2. В `authorized_keys` этого пользователя добавить ключ панели. Если его нет, команда остановится
   на проверке SSH и сама напечатает нужный публичный ключ.
3. Свободный UDP-порт (`--port`), открытый у провайдера.

## Что делает

| Шаг | Действие | Повторный запуск |
|---|---|---|
| panel | запись сервера, проверка SSH, развёртывание AmneziaWG 3 | пропускает готовое |
| bot | сервер в `PANEL_PROTOCOLS`, в правах API-ключа бота и в разрешённых серверах всех пользователей; пересоздаётся только контейнер бота | пропускает готовое |
| probe | служебный профиль `rf-probe <точка>` и файл цели на точке проверки | пропускает готовое |
| verify | настоящий прогон проверки для новой ноды и чтение ноды ключом бота | выполняется всегда |

`--dry-run` только показывает, что изменится. Существующие ноды команда не трогает.

## Границы

- Команда проверена полным прогоном на уже подключённой ноде (все шаги «уже сделано», проверка пройдена)
  и в режиме `--dry-run` для нового адреса. Создание и развёртывание на **новом** сервере этим сценарием
  ещё не выполнялось: первый реальный запуск проводить, наблюдая за выводом.
- Запросы к панели идут с пятиминутным токеном администратора, выпущенным внутри контейнера backend;
  для этого нужен root на manager. Пароль и 2FA не меняются.
- Серверные ключи ноды остаются на ней; в backup попадают только ключи ноды, размещённой на manager.
- Если развёртывание оборвалось, перед повтором посмотреть состояние в панели: команда не запускает
  развёртывание заново, пока панель считает его выполняющимся.
- Удаление ноды: отозвать служебный профиль, убрать сервер из `PANEL_PROTOCOLS`, прав ключа и панели — вручную.
