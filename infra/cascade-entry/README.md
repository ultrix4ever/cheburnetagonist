# Каскадный вход с автоматическим выбором выхода

Вход AmneziaWG 3.1 внутри страны, клиенты которого выходят в интернет через одну из обычных нод.
Нужен, когда прямой путь от человека до зарубежной ноды закрыт, а от сервера входа — открыт.

```
клиент → вход (awg0) → один из каналов awgx<N> → нода N → интернет
```

## Как устроено

- Отдельный контейнер `amnezia-awg2` в своей сети Docker (`br-cascade`); каталог на хосте
  `/opt/amnezia/awg-cascade` смонтирован как `/opt/amnezia/awg`. Панель управляет клиентами через
  протокол `awg`, поэтому в боте сервер записан как `"<id>":"awg"`.
- На каждой ноде-выходе выпущен обычный служебный профиль; его файл лежит в `exits/awgx<N>.conf`
  (`Table = off`, `MTU = 1280`, без DNS).
- `entry-start.sh` — точка входа контейнера: сначала запреты, потом интерфейсы.
- `failover.sh` каждые 10 секунд проверяет текущий канал настоящим трафиком (ping через канал).
  После двух неудач подряд переводит клиентов на первый рабочий канал: сначала по списку `exit-order`
  (основные выходы, по одному номеру ноды в строке, лучший первым), и только если не работает ни один
  из них — по списку `exit-last` (запасные выходы).
  Внутри основных выбор липкий: обратно сам не возвращается, смена выхода рвёт соединения.
  С запасного выхода возвращается сам: раз в 30 секунд проверяет основные строже (4 ответа из 4)
  и переходит после трёх удачных проверок подряд.
  Журнал — `failover.log`, текущее состояние — `failover.state` (время и номер ноды или `none`).
  Перезапущенный переключатель продолжает с маршрута, который уже обслуживает клиентов.
- Если не работает ни один канал, маршрут снимается: клиент подключён, но трафик не идёт.
  Напрямую с адреса входа клиентский трафик не выходит никогда.
- `rf-cascade-egress-guard` — второй запрет на хосте: сеть контейнера может отправлять пакеты только
  на адреса и порты из `exits/*.conf`. `rf-cascade-health` раз в 30 секунд возвращает правила и
  перезапускает контейнер, если пропал интерфейс, запрет или сам переключатель.

## Добавить или убрать выход

1. Выпустить на ноде служебный профиль, привести его к виду остальных файлов в `exits/`.
2. Положить файл как `exits/awgx<N>.conf`, дописать номер в `exit-order` или `exit-last`.
3. `systemctl start rf-cascade-health` (обновит правила хоста), затем `docker restart amnezia-awg2`.

Списки `exit-order` и `exit-last` читаются на каждом проходе: поменять порядок можно без перезапуска.
На уже выбранный выход новый порядок действует при следующем переключении.

Убрать — в обратном порядке, профиль на ноде отозвать последним.

## Чего не делать

- Не запускать для этого сервера развёртывание, обновление и пересборку из панели: они вернут
  стандартную точку входа контейнера. Запреты хоста утечку не допустят, но каскад придётся поднимать заново.
- Не отзывать служебные профили на нодах-выходах, пока вход работает.

## Проверено при вводе в работу

Настоящий клиент из другой сети: вход, HTTPS, адрес выхода; блокировка текущего выхода — переход на
следующий за ~35 секунд; возврат выхода — остаёмся на новом; блокировка всех — трафика нет;
снятие блокировки — восстановление; перезапуск контейнера — восстановление.
